## 权限边界复核

开放认领候选人的权限遵循最小必要原则：

- 可读：项目详情、任务列表与详情、成员列表、时间线、项目 Wiki、项目公告。
- 不可读：文件列表、项目与字幕冲突明细等正式成员数据。
- 不可读写：任务评论等内部协作数据。
- 不可写：Wiki 修改、合并、审核、冲突处理、项目配置和成员管理。
- 认领成功：整项或翻译分段认领会创建或恢复 `ProjectMember`，之后按正式成员和具体任务职责授权。

文件、冲突和字幕敏感对象明确禁用候选人旁路；仅拥有匹配标签不能替代正式项目成员关系。

## 数据库升级行为

超级管理员迁移按创建时间保留最早账号，其他历史重复账号降级为 `group_admin`，再写入唯一标记并创建唯一索引。应用启动升级逻辑对 SQLite、PostgreSQL 和 MySQL 执行同等归一化，以避免旧部署跳过迁移后继续处于不一致状态。

SQLite 还增加了 `UploadPolicy.max_size_bytes` 类型修复迁移，避免旧库中的 `INTEGER` 与 Prisma `BigInt` 映射不一致导致项目查询失败。

## 剩余风险

### 中：翻译区间并发认领仍依赖事务内查询

当前实现会在写入前检查同一分集的区间重叠，能正确拒绝顺序请求；但数据库没有“区间不可重叠”的排他约束。两个真正并发、且都在对方提交前完成检查的事务，理论上仍可能写入重叠区间。

建议：PostgreSQL 部署使用 range 类型与 exclusion constraint；其他数据库使用分集级互斥锁或可序列化事务，并增加双连接并发集成测试。整项任务认领已使用条件更新，不受此项影响。
